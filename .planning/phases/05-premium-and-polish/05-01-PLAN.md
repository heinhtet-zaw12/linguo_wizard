Create a new file `lib/core/services/scenario_service.dart` that provides:

**FirestoreScenarioService** — stateless, injectable service:
```dart
class FirestoreScenarioService {
  final FirebaseFirestore _db = FirebaseFirestore.instance;
  static const String _collection = 'scenarios';
  static const String _cacheKey = 'cached_scenarios';
  static const String _cacheTimestampKey = 'cached_scenarios_timestamp';
  static const Duration _cacheTtl = Duration(hours: 24);
}
```

Methods:
1. `Future<List<Scenario>> fetchAll({int? limit, DocumentSnapshot? startAfter})` — paginated fetch from Firestore. If limit is null, fetches all (for caching). Returns typed list.

2. `Future<List<Scenario>> getCachedScenarios()` — reads from SharedPreferences, deserializes JSON list. Returns empty list if no cache.

3. `Future<void> cacheScenarios(List<Scenario> scenarios)` — serializes to JSON, writes to SharedPreferences with timestamp.

4. `Future<bool> isCacheStale()` — checks if cache is older than 24h or doesn't exist.

5. `Future<List<Scenario>> getScenarios()` — the main entrypoint: loads from cache first (instant), then if stale, background-fetches from Firestore, updates cache, returns fresh list. For the first call when cache is empty, blocks on Firestore fetch.

6. `Future<DocumentSnapshot?> getLastVisible(List<Scenario> scenarios)` — helper for pagination, returns the last Firestore document snapshot for a given list (used as startAfter cursor).

Implementation notes:
- Use `SharedPreferences` for cache (scenario JSON is ~1KB each × 50 = ~50KB, well under 2MB limit)
- Cache stores `List<Map<String, dynamic>>` as JSON string
- Firestore query: `.orderBy('completionCount', descending)` for popular-first ordering
- For pagination: pass `startAfterDocument` to fetchNextPage
- Handle cache corruption gracefully (try/catch, return empty list, force re-fetch)

Provider in service_providers.dart:
```dart
final scenarioServiceProvider = Provider<FirestoreScenarioService>((ref) {
  return FirestoreScenarioService();
});
```

### ViewModel (scenario_selection_viewmodel.dart)

Rewrite `ScenarioSelectionViewModel` to:

**State:**
```dart
class ScenarioSelectionState {
  final List<Scenario> allScenarios;       // complete list from cache/Firestore
  final List<Scenario> displayScenarios;   // currently visible (paginated + filtered)
  final String? selectedCefrLevel;
  final String? selectedCategory;
  final String searchQuery;
  final bool isLoading;
  final bool isLoadingMore;
  final bool hasMore;
  final DocumentSnapshot? lastDocument;    // for pagination cursor
}
```

**Key behavior:**
1. `build()` → loads from `FirestoreScenarioService.getScenarios()`. First call blocks on cache. Sets allScenarios and calculates displayScenarios (paginated subset).
2. `setCefrFilter(String?)` → update filter, recalculate display list from page 0
3. `setCategory(String?)` → update category filter, recalculate from page 0. Category values: null (All), 'travel', 'work', 'social', 'academic', 'daily-life'
4. `setSearchQuery(String)` → filter by title or description containing the query (case-insensitive), reset pagination
5. `loadMore()` → if `hasMore && !isLoadingMore`, increment the page window. For simplicity with Firebase pagination: increment a `_visibleCount` by 20 each time and slice from allScenarios. Capped at allScenarios.length.
6. Filters stack: CEFR AND Category AND search query. All three can be active simultaneously.

Filter logic in `_computeDisplay()`:
```
filtered = allScenarios
  .where(matchesCefr)     // if selectedCefrLevel != null
  .where(matchesCategory)  // if selectedCategory != null
  .where(matchesSearch)    // if searchQuery not empty
  .toList()
  ..sort(completionCount descending)
displayScenarios = filtered.take(_visibleCount).toList()
hasMore = _visibleCount < filtered.length
```

**Initial _visibleCount:** 20 (or allScenarios.length if less).

**Sorting:** By completionCount descending (popular first) by default. Add sort option: "Popular" (default) and "Newest" (by createdAt timestamp — add field to model if needed, or skip in Wave 1).
